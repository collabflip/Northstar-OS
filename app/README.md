# Northstar SellerOS

Bilingual (EN / fr-CA), Canada-native **autonomous real-estate operating-system demo pilot** for licensed Canadian agents and brokerages — optimized to win and service residential seller listings, with buyer-inquiry conversion and transaction coordination. Multi-tenant SaaS architecture with durable workflows, typed state, human approvals, tamper-evident audit, and **Canadian compliance by construction** (CASL, DNCL/UTR, PIPEDA, FINTRAC/PCMLTFA, TRESA/RECO, human rights).

> **Status: demo pilot.** Suitable only for supervised Ontario testing using unmistakably fictional data, human approval gates, and mock integrations — not for production use. The independent red-team verdict is **Pilot Ready** (not "Production Ready"); see `docs/residual-risk-template.md` and the red-team outputs for the honest blocker list.

## What it is (and isn't)

- **Is:** a working Ontario seller-journey vertical slice — lead capture → consent → CRM → property dossier → valuation support → listing strategy → payload-bound human approval → compliant campaign send → offer room → transaction coordination — backed by 20 contract-tested agent cores (3 wired into production call paths today), a versioned Ontario policy pack, and a fail-closed commit-time policy gate on every external side effect.
- **Isn't:** a generic chatbot, a landing page, an appraisal tool, or legal advice. Breadth items ship as interfaces/fixtures with **truthful status**, never as fake functionality (spec §15).

## Architecture at a glance

React 19 + Vite SPA (`src/`) · Hono + tRPC 11 API (`api/`) · MySQL + Drizzle (`db/`) · typed agent framework (`api/agents/`, 20 cores, one contract — 3 runtime-wired) · policy kernel (`api/policy/`, Ontario production pack + BC/AB/QC fixtures) · event-sourced durable runner with outbox + idempotency (`api/workflows/`) · model gateway with PII/injection/exfiltration controls (`api/gateway/`) · integrations (`api/integrations/`) · evals (`evals/`). Binding detail: `docs/ARCHITECTURE_CONTRACT.md`; decisions: `docs/adrs.md` (ADR-001…005).

## Quickstart

```bash
npm install && npm run db:migrate && npm run db:seed && npm run dev
```

> ### 数据库与迁移 (Database & migrations)
>
> - **`npm run db:migrate`** (`scripts/db-migrate.mjs`) applies the committed, versioned migrations in `db/migrations/` (generated by `npx drizzle-kit generate`). It is idempotent and safe for **both fresh and existing databases** — applied migrations are journaled and never re-run, and it never truncates or drops data (including the `audit_log` hash chain). Use this in CI and for any shared/deployed database.
> - **`npm run db:push` is a dev-only schema sync** and is NOT idempotent on TiDB. On a database that already has the schema it may prompt to **TRUNCATE `audit_log`** (the tamper-evident chain) and fails non-interactively. **NEVER run `db:push` against a database containing production data** — never in CI, never against shared or deployed databases. See `docs/deployment-guide.md` §1.

Requires Node.js ≥ 22.22.0 (required by react-router 8.3.0; CI pins 22.22.0); `DATABASE_URL` and OAuth vars are portal-provided (see `docs/deployment-guide.md` §2 — no Docker/Temporal/Python needed). Then follow **`docs/demo-script.md`** (15-minute reviewer walkthrough with the seeded cast: Maya Chen, the Pelletiers / DEMO-ON-PROPERTY-001, Jonah Whitfield — including the worker-restart resume and a blocked CASL send).

### Environment variables

Mirrors `.env.example` exactly — every variable the code reads (`api/`, `db/`, `evals/`, `scripts/`). "Required" = boot fails without it only when `NODE_ENV=production`; development falls back to mocks. Detail per var: `docs/deployment-guide.md` §2.

| Variable | Required | Purpose (one line) |
|---|---|---|
| `APP_ID` | Production | OAuth application client ID; expected session-JWT `clientId` |
| `APP_SECRET` | Production | OAuth client secret **and** session-JWT signing key (rotate together) |
| `KIMI_AUTH_URL` | Production | Kimi OAuth server base URL (authorize, token exchange, JWKS) |
| `KIMI_OPEN_URL` | Production | Kimi Open Platform base URL (profile fetch) |
| `OWNER_UNION_ID` | Optional | App creator's union ID — gets admin role on first login |
| `DATABASE_URL` | Production | MySQL/TiDB connection string (app, `db:push`, `db:seed`, live-DB tests) |
| `NODE_ENV` | Optional | `production` turns missing required vars into boot failures |
| `PORT` | Optional (default `3000`) | API listen port |
| `DRAINER_INTERVAL_MS` | Optional (default `30000`; `0` disables) | Outbox drainer worker cadence |
| `MODEL_GATEWAY_BASE_URL` | Optional | OpenAI-compatible live-model endpoint; unset → deterministic mock only |
| `MODEL_GATEWAY_API_KEY` | Only with live provider | Provider key — never commit, never place in model context/logs |
| `MODEL_GATEWAY_MODEL` | Optional (default `kimi-k3`) | Model name recorded to `model_calls.modelVersion` |
| `VITE_APP_ID` | Optional — **not read by the current frontend** | Platform convention only (SPA uses relative `/api/oauth/login`) |
| `VITE_KIMI_AUTH_URL` | Optional — **not read by the current frontend** | Platform convention only |

### Health endpoints

- `GET /api/trpc/ping` — tRPC health query (`api/router.ts`), returns `{ ok, ts }`.
- `GET /api/livez` / `GET /api/readyz` — liveness/readiness probes for staging environments (added on the release engineering branch; available once merged).

## Test & eval commands

```bash
npm run test     # unit + Ontario policy scenarios + security (cross-tenant, injection,
                 # exfiltration, stale approval, duplicate webhook, restart-resume)
                 # + API integration
npm run evals    # 131 generated golden scenarios (spec §13 categories, incl. EN/fr-CA
                 # bilingual parity) + 85-check seller-conversation simulator
                 # → evals/report.md
```

`evals/report.md` reports exact counts, pass rates, representative failures, corrections, and limitations.
